# Architecture

Next.js App Router serves the marketplace and API on Vercel. PostgreSQL (Neon when configured) stores accounts, hashed sessions, rate-limit windows, email verification tokens, auctions, commitments, reveals, invoices, wallet notes, worker replay nonces, and health. Drizzle owns the schema and SQL migrations. Production signup requires Resend verification; the provider key stays server-side.

The separate Node worker talks to a local authenticated Zallet RPC and to the app over HTTPS using HMAC signed timestamps and one-use nonces. It creates one wallet account per invoice, derives an Orchard receiver, and verifies it using `z_listunifiedreceivers`. The account boundary matters because Zallet's `z_listunspent` address filter may return notes belonging to any address in that account. The worker filters `sapling`, `orchard`, and post-upgrade `ironwood` notes, excludes change and transparent outputs, and rejects amounts outside exact JavaScript integer range. When configured, it cross-checks active-chain transactions and confirmations against Zebra. Three confirmations and at least the invoice amount produce confirmed status; duplicate notes are keyed by txid and output index. A missing/reorganized note can reduce status on a later scan.

`ZCASH_NETWORK` is stored on each invoice. A regtest worker cannot take a testnet invoice, and vice versa. Vercel never hosts a wallet daemon or spending key. The worker host does hold wallet authority in the tested Z3 setup, so the operator is a custodian of any received funds. The app has no seller payout or escrow. The application database is not protected by Zcash shielding.

`z_listunspent` is an unspent-note snapshot rather than a permanent payment journal. Do not spend from invoice accounts while monitored. The Z3-packaged Zallet version tested here briefly omitted `wallet_tip`; the worker only continues in that case with a matching Zebra node tip and cross-checks each note transaction against Zebra. This regtest behavior is not a substitute for public testnet validation.
